# 음식한눈 · foodhannun

음식명과 재료를 검색하고 레시피·재료·영양 정보·주의 성분·장보기 목록을 함께 살펴보는 모바일 웹입니다.

**기본 HTML / CSS / JavaScript로 구현했습니다. 설치와 빌드가 필요 없으며 `index.html`을 열면 동작합니다.**

## 현재 구현

| 기능 | 동작 |
| --- | --- |
| 음식·재료 검색 | 이름, 주요 재료, 조리법, 분류 검색; 공백 무시·동의어·한글 초성 지원 |
| 검색 보조 | 추천 재료, 자동 제안, 최근 검색어, 무결과 안내 |
| 필터 | 조리법, 음식 종류, 재료명 기준 주의 성분 제외 |
| 정렬 | 기본 순, 이름 순 |
| 레시피 상세 | 공식 음식 사진, 재료 원문·분량, 원문 순서의 조리 단계 |
| 영양 | 원본 열량·탄수화물·단백질·지방·나트륨 표시; 기준 중량 누락 표시 |
| 알레르기 참고 | 재료명에서 발견한 성분 단서·복합 원재료 확인 안내 |
| 저장한 음식 | 브라우저에 즐겨찾기 저장·해제 |
| 장보기 | 재료별 담기, 모두 담기, 구매 완료 체크, 삭제, 목록 복사 |
| 구매처 | 재료명으로 네이버쇼핑 검색 결과 연결; 가격·재고·제휴 API 없음 |
| 내 요리 메모 | 음식별 메모를 현재 브라우저에 저장 |
| 공유 | 음식 ID를 포함한 URL; Web Share 지원 시 공유창, 그 외 복사 |
| 음성 검색 | HTTPS와 지원 브라우저에서 사용자 클릭 후 브라우저 음성 인식 사용 |
| 출처 | 공식 출처 링크, 데이터 범위, 가져온 날짜, 제공하지 않는 항목 안내 |

검색어 예: `두부`, `달걀`, `계란찜`, `새우`, `오이`, `토마토`, `북어국`, `ㄷㅂ`.

저장한 음식·메모·장보기는 계정 동기화 없이 현재 브라우저의 localStorage에 보관됩니다. 브라우저 데이터를 삭제하면 지워지며, 저장 공간 사용이 차단된 경우에는 이번 화면에서만 유지됩니다. 장보기에는 담을 당시 재료와 분량을 보관합니다.

## 실제 데이터와 제공 범위

초기 데이터는 [식품안전나라 COOKRCP01 공개 샘플 API](https://openapi.foodsafetykorea.go.kr/api/sample/COOKRCP01/json/1/5)에서 내려받은 **실제 레시피 5건**입니다. 테스트용 가상 레시피·평점·리뷰를 생성하지 않았습니다.

| 원문 ID | 음식명 |
| --- | --- |
| 28 | 새우 두부 계란찜 |
| 29 | 부추 콩가루 찜 |
| 31 | 방울토마토 소박이 |
| 32 | 순두부 사과 소스 오이무침 |
| 33 | 사과 새우 북엇국 |

데이터 파일은 정적 스냅샷입니다. 이용자의 검색마다 외부 API를 호출하지 않으며, 전체 데이터베이스가 수록된 상태는 아닙니다. `totalAvailable`은 원본 API가 응답한 전체 건수이고, 실제 수록 건수는 `meta.count`입니다.

### 데이터 해석

- 다섯 레시피 모두 `INFO_WGT`가 비어 있습니다. 화면에서 영양값을 임의로 100g 또는 실제 섭취 1인분 기준으로 환산하거나 순위를 매기지 않습니다.
- 공식 API에는 전체 조리시간·난이도·사용자 리뷰·평점·정규 알레르기 필드가 없습니다. 이 값들을 임의로 채우지 않습니다.
- 알레르기 표시는 원재료 텍스트의 단서를 찾는 기능입니다. 미검출은 안전을 뜻하지 않으며 모든 알레르겐·세부 배합·교차 접촉을 포괄하지 않습니다.
- 북엇국 원문은 조리 단계 번호 `2, 3, 5`만 제공합니다. 누락 사실과 원문 번호를 그대로 표시합니다.
- 원본 `RCP_NA_TIP`의 포괄적인 건강 효능 문장은 앱의 건강 인사이트로 자동 재사용하지 않습니다.
- 음식 사진은 원본 API가 제공한 이미지를 내려받아 WebP로 압축했습니다. 원문은 `data/raw-sample.json`에 보존했습니다.
- `fetchedAt`은 실제 데이터 가져온 시간입니다. 원문 개별 레코드의 최신 수정일을 뜻하지 않습니다.

## 파일 구성

| 경로 | 역할 |
| --- | --- |
| `index.html` | 검색 홈, 필터, 카드 목록, 상세·장보기·출처 모달의 기본 HTML |
| `assets/styles.css` | 모바일 및 데스크톱 반응형 스타일 |
| `assets/app.js` | 검색·필터·저장·장보기·메모·공유 동작 |
| `assets/data.js` | 브라우저가 바로 읽는 `window.FOOD_DATA` |
| `assets/images/` | 공식 대표 사진 5장과 이미지 실패 시 대체 SVG |
| `assets/favicon.svg` | 서비스 아이콘 |
| `data/recipes.json` | 출처 메타데이터와 정규화한 레시피 |
| `data/raw-sample.json` | 공개 API 원문 |
| `scripts/sync-recipes.py` | 공개 샘플 또는 인증키로 전체 레시피 수집 |
| `scripts/deploy-pages.sh` | GitHub 저장소 생성·코드 푸시·Pages 설정을 수행하는 실행 스크립트 |
| `.nojekyll` | GitHub Pages에서 정적 파일 그대로 제공 |

HTML과 CSS/JS의 경로는 상대경로입니다. GitHub Pages 프로젝트 경로에서 별도 라우터 없이 동작하며, `dist` 경로는 사용하지 않습니다.

## 실행

압축을 풀고 `index.html`을 브라우저에서 열면 됩니다. 기본 검색과 목록·메모·장보기에는 로컬 서버가 필요 없습니다. 음성·기기 공유·자동 클립보드 복사처럼 브라우저가 HTTPS를 요구하는 기능은 배포 환경에서 지원 여부를 확인합니다.

## GitHub 저장소 생성과 Pages 배포

2026-10-20(한국 시간) [softm/foodhannun 저장소](https://github.com/softm/foodhannun) 생성과 [음식한눈 서비스](https://softm.github.io/foodhannun/)의 GitHub Pages 배포를 완료했습니다.

아래 스크립트는 사용자가 로컬 환경에서 선택 실행할 수 있는 배포 보조 도구입니다. Git과 [GitHub CLI](https://cli.github.com/)가 설치되고 `gh auth login`으로 본인의 GitHub 계정에 로그인한 환경에서 프로젝트 폴더의 다음 명령을 실행합니다.

```bash
bash scripts/deploy-pages.sh
```

스크립트는 연결된 계정이 `softm`인지 확인하고 새 공개 저장소를 만든 뒤, `main` 브랜치의 루트(`/`)를 Pages 소스로 설정합니다. 다른 저장소의 기존 이력을 덮어쓰거나 강제 푸시하지 않습니다. 이미 사용 중인 저장소를 새 폴더에서 발견하면 중단합니다. 같은 저장소의 기존 체크아웃에서는 일반 푸시로 갱신할 수 있습니다.

배포 설정값:

| 설정 | 값 |
| --- | --- |
| 저장소 | [softm/foodhannun](https://github.com/softm/foodhannun) |
| 공개 범위 | Public |
| Pages source | Deploy from a branch |
| Branch | `main` |
| Folder | `/ (root)` |
| Build command | 없음 |
| 서비스 주소 | [음식한눈](https://softm.github.io/foodhannun/) |

별도 Actions 배포 워크플로와 브랜치 배포를 동시에 추가하지 않습니다. [GitHub Pages REST 문서](https://docs.github.com/en/rest/pages/pages#create-a-github-pages-site)와 [gh repo create 문서](https://cli.github.com/manual/gh_repo_create)를 기준으로 작성했습니다.

## 데이터 갱신

Python 3.10 이상에서 공개 샘플 5건을 갱신합니다. 수집 스크립트는 표준 라이브러리만 사용합니다.

```bash
python3 scripts/sync-recipes.py
```

정식 API 이용 신청과 인증키 준비 후, `FOODSAFETY_API_KEY` 환경변수를 설정한 환경에서 전체 데이터를 가져올 수 있습니다.

```bash
python3 scripts/sync-recipes.py --full
```

인증키를 `assets/app.js`, HTML, 공개 JSON, README에 넣지 마세요. `--full`은 키가 없으면 중단하며 기존 데이터를 보존합니다. 원본 응답·출력 파일에 키가 들어 있지 않은지도 검사합니다. 모든 페이지 수집과 개수 검증을 마친 뒤 정적 파일을 교체합니다. 자동 예약 수집은 설정하지 않았습니다.

초기 5개 대표 사진은 로컬 파일을 사용합니다. 새 레시피는 공식 HTTPS 이미지 주소를 사용하며, 수집 스크립트 자체는 사진을 새로 내려받거나 압축하지 않습니다. 향후 대량 이미지 로컬 수집은 별도 확장 작업입니다. 원재료 텍스트 분리는 모든 비정형 원문에서 완벽하지 않으므로 전체 수집 후 표본 검토가 필요하고, 화면에는 원문도 함께 제공합니다.

## 다음 확장

1. 정식 키로 전체 레시피를 수집하고 미검색 음식·동의어를 보강합니다.
2. 영양 기준 중량이 명확한 공식 영양 데이터와 메뉴별로 검증해 매핑합니다.
3. 조리시간·난이도는 확인 가능한 별도 데이터나 검수된 운영 데이터를 연결합니다.
4. 공개 리뷰·사용자 계정·기기 간 동기화는 백엔드를 연결할 때 추가합니다.
5. 이미지 음식 인식과 실제 가격·재고·제휴 API는 각각 연동이 필요합니다.

## 검증

자바스크립트 문법, HTML의 필수 ID/중복 ID, 정적 경로, 정규화 JSON과 브라우저 데이터의 일치, 공식 이미지 파일, 키 없는 전체 수집 실패 시 기존 데이터 보존을 점검했습니다.

2026-10-20(한국 시간) [첫 GitHub Pages 배포 실행](https://github.com/softm/foodhannun/actions/runs/39285531798)의 build·deploy·report 단계가 모두 성공했음을 확인했습니다. 원격에 업로드한 18개 파일은 로컬 원본과 Git blob SHA가 모두 일치했습니다.

라이브 웹에서 레시피 목록 5건, `두부` 검색 결과 2건, 상세의 재료 원문과 영양 기준 중량 미제공 안내, 재료 1건의 장보기 추가·제거, 장보기 창을 닫은 뒤 레시피 상세가 유지되는 동작을 확인했습니다. 실제 모바일 기기 화면은 검증하지 않았습니다.
