음식명과 재료를 검색하고 레시피·재료·영양 정보·주의 성분·장보기 목록을 함께 살펴보는 모바일 웹입니다.

**기본 HTML / CSS / JavaScript로 구현했습니다. 설치와 빌드가 필요 없으며 `index.html`을 열면 동작합니다.**

## 현재 구현

| 기능 | 동작 |
| --- | --- |
| 음식·재료 검색 | 이름, 주요 재료, 조리법, 분류 검색; 공백 무시·동의어·한글 초성 지원 |
| 검색 보조 | 추천 재료, 자동 제안, 최근 검색어, 무결과 안내 |

| 목록 표시 | 첫 24개를 표시하고 24개씩 더보기 또는 검색 결과 전체 보기; 상세 닫기·저장 후에도 확장한 목록 유지 |
| 목록 선택 | 카드 전체를 눌러 해당 음식 상세 열기; 최근 선택 카드 테두리·표시, 저장 버튼은 독립 동작 |
| 정렬 | 기본 순, 이름 순 |

| 영양 | 원본 열량·탄수화물·단백질·지방·나트륨 표시; 기준 중량 누락 표시 |
| 알레르기 참고 | 재료명에서 발견한 성분 단서·복합 원재료 확인 안내 |
| 저장한 음식 | 브라우저에 즐겨찾기 저장·해제 |
| 장보기 | 재료별 담기, 모두 담기, 구매 완료 체크, 삭제, 목록 복사 |
| 구매처 | 재료명으로 네이버쇼핑 검색 결과 연결; 가격·재고·제휴 API 없음 |
| 내 요리 메모 | 음식별 메모를 현재 브라우저에 저장 |

| 음성 검색 | HTTPS와 지원 브라우저에서 사용자 클릭 후 브라우저 음성 인식 사용 |
| 출처 | 공식 출처 링크, 데이터 범위, 가져온 날짜, 제공하지 않는 항목 안내 |

검색어 예: `두부`, `달걀`, `계란찜`, `새우`, `오이`, `토마토`, `북어국`, `ㄷㅂ`.

저장한 음식·메모·장보기는 계정 동기화 없이 현재 브라우저의 localStorage에 보관됩니다. 브라우저 데이터를 삭제하면 지워지며, 저장 공간 사용이 차단된 경우에는 이번 화면에서만 유지됩니다. 장보기에는 담을 당시 재료와 분량을 보관합니다.

## 실제 데이터와 제공 범위

현재 데이터는 [식품안전나라 COOKRCP01 레시피 API](https://www.foodsafetykorea.go.kr/api/openApiInfo.do?menu_grp=MENU_GRP31&menu_no=661&show_cnt=10&start_idx=1&svc_no=COOKRCP01)를 정식 인증키로 전체 수집한 **실제 레시피 1,156건**입니다.

| 항목 | 현재 수집본 |
| --- | --- |
| 수집 시각 | 2026-10-20 12:04:54, 한국 시간(Asia/Seoul) |
| 원본 `fetchedAt` | `2026-10-20T03:04:54Z` |
| 데이터 모드 | `official-full` |
| 실제 수록 / API 전체 건수 | 1,156 / 1,156건 |
| 고유 레시피 ID | 1,156개 |
| 영양 기준 중량 값 | 숫자 제공 285건, 미제공 871건 |

데이터 파일은 정적 스냅샷입니다. 이용자의 검색은 이 공식 데이터베이스에 수록된 레시피를 대상으로 하며 검색마다 외부 API를 호출하지 않습니다. `totalAvailable`은 수집 시점 원본 API가 응답한 전체 건수이고, 실제 수록 건수는 `meta.count`입니다. 최초 공개 샘플 5건의 원문도 별도 파일에 보존합니다.

### 데이터 해석

- `INFO_WGT`는 285건에 양의 숫자가 있고 871건은 비어 있습니다. 단위가 붙은 비숫자 중량값은 없었습니다. 기준 중량이 없는 영양값을 임의로 100g 또는 실제 섭취 1인분 기준으로 환산하거나 음식 간 순위를 매기지 않습니다.
- 공식 API에는 전체 조리시간·난이도·사용자 리뷰·평점·정규 알레르기 필드가 없습니다. 이 값들을 임의로 채우지 않습니다.
- 알레르기 표시는 원재료 텍스트의 단서를 찾는 기능입니다. 미검출은 안전을 뜻하지 않으며 모든 알레르겐·세부 배합·교차 접촉을 포괄하지 않습니다.
- 주의 성분 제외 필터를 적용하면 재료 원문이 없는 레시피도 결과에서 제외합니다.
- 영양값 5개가 모두 0인 ID `1057`과 표기된 중량보다 탄수화물 값이 큰 ID `3773`에는 원문 확인 안내를 표시합니다. 원본 값을 임의로 고치지 않습니다.
- 조리 단계 번호가 불연속인 원문은 ID `33` 사과 새우 북엇국(`2, 3, 5`)과 ID `36` 저염 된장으로 맛을 낸 황태해장국(`3, 4, 5`)입니다. 누락 단계를 만들어 채우지 않고 원문 번호를 보존합니다.
- 재료 원문이 없는 레시피는 ID `691`, `692`, `831`의 3건이며, 조리 단계가 전혀 없는 레시피는 ID `2980` 비타 오이 물김치 1건입니다. 제공되지 않은 정보를 임의로 생성하지 않습니다.
- 원본 `RCP_NA_TIP`의 포괄적인 건강 효능 문장은 앱의 건강 인사이트로 자동 재사용하지 않습니다.
- 초기 대표 사진 5장은 공식 원본을 내려받아 WebP로 압축했습니다. 추가 레시피 사진은 공식 HTTPS 이미지 주소를 사용하며, 전체 원문은 `data/raw-full.json`에 보존했습니다.
- `두부200g`, `두부(200g)`처럼 명확한 분량은 이름과 분리하되 원문의 숫자·단위·괄호 표기를 유지합니다. 괄호가 닫히지 않거나 여러 재료가 섞인 원문(ID `523`, `781`, `808` 등)은 임의로 교정하지 않습니다. 각 재료의 `raw`와 전체 `ingredientText`를 함께 보존합니다.
- `fetchedAt`은 실제 데이터 가져온 시간입니다. 원문 개별 레코드의 최신 수정일을 뜻하지 않습니다.

HTML과 CSS/JS의 경로는 상대경로입니다. GitHub Pages 프로젝트 경로에서 별도 라우터 없이 동작하며, `dist` 경로는 사용하지 않습니다.

현재 전체 수집본의 파일 크기는 브라우저 데이터 `assets/data.js` 약 3.36MB, 정규화 JSON 약 4.70MB, 전체 원문 JSON 약 3.32MB입니다. 화면은 `assets/data.js`를 읽으며 원문·정규화 JSON을 추가로 다운로드하지 않습니다. 서버의 전송 압축 적용 여부에 따라 실제 네트워크 전송량은 달라질 수 있습니다.

## 실행

압축을 풀고 `index.html`을 브라우저에서 열면 됩니다. 기본 검색과 목록·메모·장보기에는 로컬 서버가 필요 없습니다. 음성·기기 공유·자동 클립보드 복사처럼 브라우저가 HTTPS를 요구하는 기능은 배포 환경에서 지원 여부를 확인합니다.

## GitHub 저장소 생성과 Pages 배포

2026-10-20(한국 시간) [softm/foodhannun 저장소](https://github.com/softm/foodhannun) 생성과 [음식한눈 서비스](https://softm.github.io/foodhannun/)의 GitHub Pages 배포를 완료했습니다.

아래 스크립트는 사용자가 로컬 환경에서 선택 실행할 수 있는 배포 보조 도구입니다. Git과 [GitHub CLI](https://cli.github.com/)가 설치되고 `gh auth login`으로 본인의 GitHub 계정에 로그인한 환경에서 프로젝트 폴더의 다음 명령을 실행합니다.

```bash
bash scripts/deploy-pages.sh
```

스크립트는 연결된 계정이 `softm`인지 확인하고 새 공개 저장소를 만든 뒤, `main` 브랜치의 루트(`/`)를 Pages 소스로 설정합니다. 다른 저장소의 기존 이력을 덮어쓰거나 강제 푸시하지 않습니다. 이미 사용 중인 저장소를 새 폴더에서 발견하면 중단합니다. 같은 저장소의 기존 체크아웃에서는 일반 푸시로 갱신할 수 있습니다.

배포 설정값:

| 설정 | 값 |
| --- | --- |
| 저장소 | [softm/foodhannun](https://github.com/softm/foodhannun) |
| 공개 범위 | Public |
| Pages source | Deploy from a branch |
| Branch | `main` |
| Folder | `/ (root)` |
| Build command | 없음 |
| 서비스 주소 | [음식한눈](https://softm.github.io/foodhannun/) |

별도 Actions 배포 워크플로와 브랜치 배포를 동시에 추가하지 않습니다. [GitHub Pages REST 문서](https://docs.github.com/en/rest/pages/pages#create-a-github-pages-site)와 [gh repo create 문서](https://cli.github.com/manual/gh_repo_create)를 기준으로 작성했습니다.

## 데이터 갱신

Python 3.10 이상에서 갱신하며 수집 스크립트는 표준 라이브러리만 사용합니다. 현재처럼 전체 데이터가 저장된 상태에서는 `FOODSAFETY_API_KEY` 환경변수가 준비된 환경에서 다음 명령을 실행합니다.

```bash
python3 scripts/sync-recipes.py --full
```

공식 공개 샘플 5건으로 명시적으로 전환하거나 샘플을 갱신하려면 다음 명령을 사용합니다.

```bash
python3 scripts/sync-recipes.py --sample
```

`--full`과 `--sample`은 동시에 지정할 수 없습니다. 기존 모드가 `official-full`인데 옵션 없이 실행하면 API 호출과 파일 변경 없이 중단합니다. 처음 실행하거나 기존 모드가 샘플일 때에는 옵션 없는 명령의 기본 샘플 동작을 유지합니다.

인증키를 `assets/app.js`, HTML, 공개 JSON, README에 넣지 마세요. `--full`은 키가 없으면 중단하며 기존 데이터를 보존합니다. 원본 응답·출력 파일에 키가 들어 있지 않은지도 검사합니다. 모든 페이지 수집과 개수 검증을 마친 뒤 정적 파일을 교체합니다.

`.github/workflows/sync-recipes.yml`을 통해 **매일 06:20(한국 시간)** 자동 갱신을 시도합니다. 저장소의 Actions Secret에 `FOODSAFETY_API_KEY`가 등록되어 있으면 전체 수집 → 건수·고유 ID·브라우저 스냅샷 검증 → 변경된 데이터 파일만 커밋/푸시합니다. Secret이 없으면 기존 데이터를 변경하지 않고 해당 실행을 안전하게 건너뜁니다. GitHub Pages는 `main` 브랜치 루트 배포를 사용하므로 데이터 커밋이 발생하면 기존 Pages 흐름으로 반영됩니다.

Secret 등록 위치: `Settings → Secrets and variables → Actions → New repository secret`. 이름은 반드시 `FOODSAFETY_API_KEY`로 설정합니다. 키 값은 문서나 소스에 커밋하지 않습니다.

초기 5개 대표 사진은 로컬 파일을 사용합니다. 새 레시피는 공식 HTTPS 이미지 주소를 사용하며, 수집 스크립트 자체는 사진을 새로 내려받거나 압축하지 않습니다. 향후 대량 이미지 로컬 수집은 별도 확장 작업입니다. 원재료 텍스트 분리는 비정형 원문 전체를 완벽하게 해석하지 못하므로 수집 후 표본 검토와 원문 확인이 필요합니다.

2. 영양 기준 중량이 명확한 공식 영양 데이터와 메뉴별로 검증해 매핑합니다.
3. 조리시간·난이도는 확인 가능한 별도 데이터나 검수된 운영 데이터를 연결합니다.
4. 공개 리뷰·사용자 계정·기기 간 동기화는 백엔드를 연결할 때 추가합니다.
5. 이미지 음식 인식과 실제 가격·재고·제휴 API는 각각 연동이 필요합니다.

## 검증

자바스크립트 문법, HTML의 필수 ID/중복 ID, 정적 경로, 정규화 JSON과 브라우저 데이터의 일치, 공식 이미지 파일, 키 없는 전체 수집 실패 시 기존 데이터 보존을 점검했습니다. 모바일 검색 입력 중 끝 공백이 자동검색 렌더링으로 사라지지 않도록 보정했고, 재료 담기·전체 담기·장보기 항목 삭제/정리 후 키보드 포커스가 다음 조작 위치로 이어지도록 보완했습니다.

### 최초 공개 샘플 배포

2026-10-20(한국 시간) [첫 GitHub Pages 배포 실행](https://github.com/softm/foodhannun/actions/runs/39285531798)의 build·deploy·report 단계가 모두 성공했음을 확인했습니다. 원격에 업로드한 18개 파일은 로컬 원본과 Git blob SHA가 모두 일치했습니다.

최초 샘플 배포 당시 라이브 웹에서 레시피 목록 5건, `두부` 검색 결과 2건, 상세의 재료 원문과 영양 기준 중량 미제공 안내, 재료 1건의 장보기 추가·제거, 장보기 창을 닫은 뒤 레시피 상세가 유지되는 동작을 확인했습니다. 실제 모바일 기기 화면은 검증하지 않았습니다.

### 전체 수집 및 변환 점검

전체 응답·정규화 목록·고유 ID가 모두 1,156건임을 확인했습니다. 개선한 파서로 전체 원문을 메모리에서 재변환해 577개 레시피의 재료 6,537항목 분리를 개선했고, 재료별 `raw`, 전체 `ingredientText`, 영양값과 조리 단계가 보존됨을 대조했습니다. 실제 데이터와 네트워크에 접근하지 않는 별도 모드 검사로 기존 전체 데이터의 무옵션 덮어쓰기 차단, 명시적 `--sample` 전환, 초기 샘플 기본값, 옵션 배타 적용과 키 없는 `--full` 중단을 확인했습니다.

### 승인된 공식 원재료·안전 데이터 연결

- 7개 OpenAPI 원본은 `data/collection/{서비스}/`에 보존하며, 원본별 검색과 정확한 번호 조회 인덱스는 `data/food-safety/`에 둡니다. 실제 검증 건수는 [수집 현황](data-status.html)을 기준으로 합니다.
- 제품의 품목제조보고번호 → I1250·C002·I0490·과거 C005, I1250의 업소 인허가번호 → I0580을 정확히 연결합니다. HACCP 업소 자료는 개별 제품 인증 판정이 아닙니다.
- 레시피 재료의 **원료 정보**는 공식 원료명·이명에 맞는 I1020·I2520 자료와 사용 부위·조건을 표시합니다. C005는 2018년 이후 갱신 중단 자료입니다.
- [공식 자료 검색](food-safety.html)에서 원본 종류별 전체 자료를 검색합니다. 브라우저에 인증키를 넣지 않습니다.
