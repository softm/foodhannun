# 음식한눈 통합 기획서

최종 갱신: 2026-10-20  
서비스명: 음식한눈  
저장소: https://github.com/softm/foodhannun  
운영: https://softm.github.io/foodhannun/

## 1. 한 줄 정의

**음식명을 한 번 검색하면 레시피·재료·영양·알레르기 참고정보·관련 제품·식품안전·구매정보를 한 화면에서 연결해 주는 음식 통합검색 서비스.**

## 2. 목표

음식 관련 정보가 레시피 사이트, 영양 DB, 제품 DB, 식품안전 서비스, 쇼핑몰 등에 분산된 문제를 해결한다.

사용자는 음식명 또는 재료명 하나만 검색하고 다음 정보를 연속적으로 확인한다.

```text
음식 검색
  ↓
레시피
  ↓
재료 · 영양
  ↓
알레르기 참고
  ↓
관련 제품 · 안전정보
  ↓
장보기 · 구매
```

## 3. 핵심 기능

| 영역 | 핵심 기능 |

## 5. 데이터 통합 모델

음식명을 중심축으로 데이터를 연결한다.

```text
Food
├─ id
├─ canonicalName
├─ aliases[]
├─ category
├─ recipes[]
├─ ingredients[]
├─ nutrition
├─ allergens[]
├─ products[]
├─ safety[]
└─ purchase[]
```

핵심 과제는 서로 다른 기관의 식품명·음식명·제품명을 하나의 표준 음식/재료 인덱스로 연결하는 것이다.

```text
식품안전나라 API
```

## 7. 자동 수집 구조

### COOKRCP01

현재 GitHub Actions에 자동수집이 설정되어 있다.

| 항목 | 설정 |
| --- | --- |
| 워크플로 | `.github/workflows/sync-recipes.yml` |
| 자동 실행 | 매일 |
| 실행 시각 | 06:20 KST |
| 수동 실행 | `workflow_dispatch` 지원 |
| 인증키 | GitHub Secret `FOODSAFETY_API_KEY` |
| 수집 방식 | 전체 수집 |
| 현재 건수 | 1,156건 |
| 검증 | 총건수·고유 ID·생성 스냅샷 검증 |
| 성공 후 | 변경 파일 자동 commit/push |
| 운영 반영 | main → GitHub Pages |

```text
매일 06:20 KST
      ↓
GitHub Actions
      ↓
공공 API 전체 수집
      ↓
정규화 / 검증
      ↓
실제 변경 비교
      ↓
변경 시 Commit + Push
      ↓
GitHub Pages
```

향후 모든 데이터 수집기도 동일한 원칙을 적용한다.

1. API 키는 GitHub Secret으로만 관리한다.
2. 브라우저에서 공공 API 인증키를 직접 사용하지 않는다.
3. 원본 데이터와 정규화 데이터를 분리한다.
4. 누락·중복·총건수를 자동 검증한다.
5. 수집 실패 시 기존 정상 데이터를 보존한다.
6. 데이터가 실제로 변경된 경우에만 운영 반영한다.
7. 데이터셋별 수집 일시와 출처를 기록한다.

## 8. 확장 시스템 구성

```text
           공공데이터 / 외부 API
                    │
   ┌────────────────┼────────────────┐
   ▼                ▼                ▼
레시피 수집       영양 수집         제품·안전 수집
   │                │                │
   └────────────────┼────────────────┘
                    ▼

                    │

             /    |     \
```

초기에는 GitHub Actions + 정적 데이터 구조를 유지하고, 데이터량·회원 기능·실시간성이 커질 때 API 서버와 검색 DB를 도입한다.

## 12. 제품 원칙

- 제공기관의 원문을 임의로 사실처럼 보정하지 않는다.
- 영양 기준량이 불명확하면 임의 환산하지 않는다.
- 알레르기 단어 탐지는 안전 판정으로 표현하지 않는다.
- 공공데이터와 자체 추론·추천을 명확히 구분한다.
- 모든 주요 데이터에는 출처와 마지막 수집시각을 표시한다.
- 데이터 수집 실패가 운영 서비스 장애로 이어지지 않도록 마지막 정상 스냅샷을 보존한다.

## 13. 최종 포지션

**음식한눈은 단순 레시피 앱이 아니라 음식명을 중심으로 레시피·재료·영양·제품·안전·구매를 연결하는 음식 통합검색 플랫폼을 목표로 한다.**


## 14. 2026-10-20 추가 수집

[실제 수집·검증 결과 및 미수집 사유](DATA-COLLECTION-2026-10-20.md)를 기준으로 관리한다. 레시피 외 영양 DB 348,370건을 확보했으며, 식품안전나라 추가 7종은 활용신청 승인 후 공식 전체파일 2,530,011행을 수집·검증했다. I0490·I0580·I1250은 전체파일 행 수와 실시간 API 참조 총건수가 달라 둘을 구분해 표시한다. 확보된 자료는 메인 통합검색·레시피 영양 후보·재료명 제품 탐색으로 연결했다.

## 15. 수집 데이터 통합 적용 (2026-10-20)

[데이터 성격·연결성 점검 결과](DATA-INTEGRATION-AUDIT.md)를 적용한다. 메인에서 레시피·음식 영양·가공식품·건강기능식품을 한 번에 검색하고 종류별로 탐색한다. 레시피 상세 영양에서는 이름 연결 후보와 원문 영양을 구분하며, 재료·장보기 및 관련 제품 탭에서 재료명으로 가공식품을 찾고 구매처 검색으로 이어진다.

레시피와 음식 영양 DB 간 공통 식품 식별자가 없어 이름 일치 26개, 포함 후보 371개, 후보 없음 759개로 구분한다. 음식명 일치만으로 영양 동등성을 보증하지 않는다. 제품 원재료·회수·업소 HACCP 원문은 아래 공식 번호 연결 범위로 적용한다. 재료명 파싱 결과를 공식 원료코드로 확정하는 표준화는 별도 검증이 필요하다.

## 16. 승인 후 공식 자료 적용 범위

제품의 품목제조보고번호와 업소 인허가번호로 원재료·회수·HACCP 원문을 연결한다. 원료 이름·이명 일치는 후보 탐색으로 구분하고 사용 부위·가공 상태·조건을 보존한다. 모든 레코드 수와 전체파일/API 총건수 차이는 [수집 현황](../data-status.html), 연결 의도와 한계는 [데이터 연결성 점검](DATA-INTEGRATION-AUDIT.md)에 기록한다. 음식 영양 기준량과 제품 영양·건강기능식품 제공단위량은 각각 유지한다.

## 17. 정기 수집·검증·자동 배포

회수 정보 매시 17분, 품목·원재료·HACCP 매일 04:00, 원료 정보·코드 월요일 05:00, 레시피 매일 06:20, 영양 DB 월요일 05:35(KST)에 수집한다. 검증된 격리 세대만 연결 인덱스와 함께 main에 반영하고 기존 Pages 빌드를 명시 요청한다. 실패 시 정상본을 보존한다. C005는 과거 자료로 정기 재수집에서 제외한다. 상세 정책은 [수집 운영 절차](DATA-COLLECTION-OPERATIONS.md)를 기준으로 한다.
