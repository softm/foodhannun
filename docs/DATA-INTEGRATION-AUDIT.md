## 연결 품질

공통 식품 식별자가 없어 식품명 후보 탐색으로 연결한다. **연결률은 기관 간 동일 식품 확인률이 아니다.**

| 레시피 연결 분류 | 수 |
| --- | ---: |
| 음식명·허용 별칭 일치 | 26 |
| 가장 구체적인 음식명 포함 후보 | 371 |
| 이름 기반 후보 없음 | 759 |
| 전체 레시피 | 1,156 |
| 화면에 제공하는 영양 후보 포인터 | 1,284 |

공백·구두점은 정규화하되 계란/달걀, 북엇국/북어국만 연결용 별칭으로 취급한다. 두부/순두부/연두부, 토마토/방울토마토 등은 검색 확장에 사용해도 동일 식품 연결에는 사용하지 않는다. 포함 후보는 음식명 3글자 이상과 가장 긴 음식명 일치만 허용한다. 원문 이름의 밑줄 뒤 원료 변형(예: 김치찌개_햄)은 해당 원료가 레시피명 또는 재료명에도 있을 때만 연결한다. 원료 변형이 없는 일반 음식 자료를 먼저 표시한다. 레시피 영양 원문은 유지하고 후보 영양을 합산·환산하지 않는다.

`data/food-links.json.gz`는 레시피 ID별 후보·근거·원본 상세 위치를 보관한다. 음식 영양 인덱스와 레시피 파일 SHA-256을 기록한다. 모든 포인터를 원본 인덱스에 대조하고, 브라우저에서 상세를 열 때 식품코드를 다시 검사한다. 후보가 없는 759개에도 재료명 제품 탐색은 제공한다.

## 실제 사용자 흐름

1. 메인 음식명 검색에서 레시피·음식 영양·가공식품·건강기능식품별 결과와 건수를 확인한다. 이름·코드·제조사·분류의 경계를 유지하여 서로 다른 필드의 글자가 이어져 일치하는 오류를 방지한다. 음식·제품만 있고 레시피가 없는 검색도 결과를 제공한다.
2. 레시피 상세 → **영양**에서 COOKRCP01 영양과 연결 후보를 구분해서 확인한다. 후보마다 근거·식품코드·기준량을 표시한다.
3. 레시피 상세 → **재료·장보기 → 관련 제품** 또는 **관련 제품** 탭에서 음식/재료별 가공식품 이름을 탐색한다.
4. 제품 선택 → 제조사·품목번호·원문 영양 → **이 제품 구매처 검색**으로 이어진다.
5. 음식 영양 상세에서도 음식명으로 연결된 레시피로 돌아갈 수 있다. 상세 원문을 닫아도 부모 레시피 화면을 유지한다.
6. 조리법·주의성분 제외·저장 필터는 레시피 범위다. 제품을 안전한 음식으로 오해하지 않도록 적용 범위를 표시한다.
