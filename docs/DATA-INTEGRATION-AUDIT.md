## 연결 품질

공통 식품 식별자가 없어 식품명 후보 탐색으로 연결한다. **연결률은 기관 간 동일 식품 확인률이 아니다.**

| 레시피 연결 분류 | 수 |
| --- | ---: |
| 음식명·허용 별칭 일치 | 26 |
| 가장 구체적인 음식명 포함 후보 | 371 |
| 이름 기반 후보 없음 | 759 |
| 전체 레시피 | 1,156 |
| 화면에 제공하는 영양 후보 포인터 | 1,284 |

공백·구두점은 정규화하되 계란/달걀, 북엇국/북어국만 연결용 별칭으로 취급한다. 두부/순두부/연두부, 토마토/방울토마토 등은 검색 확장에 사용해도 동일 식품 연결에는 사용하지 않는다. 포함 후보는 음식명 3글자 이상과 가장 긴 음식명 일치만 허용한다. 원문 이름의 밑줄 뒤 원료 변형(예: 김치찌개_햄)은 해당 원료가 레시피명 또는 재료명에도 있을 때만 연결한다. 원료 변형이 없는 일반 음식 자료를 먼저 표시한다. 레시피 영양 원문은 유지하고 후보 영양을 합산·환산하지 않는다.

`data/food-links.json.gz`는 레시피 ID별 후보·근거·원본 상세 위치를 보관한다. 음식 영양 인덱스와 레시피 파일 SHA-256을 기록한다. 모든 포인터를 원본 인덱스에 대조하고, 브라우저에서 상세를 열 때 식품코드를 다시 검사한다. 후보가 없는 759개에도 재료명 제품 탐색은 제공한다.

## 실제 사용자 흐름

1. 메인 음식명 검색에서 레시피·음식 영양·가공식품·건강기능식품별 결과와 건수를 확인한다. 이름·코드·제조사·분류의 경계를 유지하여 서로 다른 필드의 글자가 이어져 일치하는 오류를 방지한다. 음식·제품만 있고 레시피가 없는 검색도 결과를 제공한다.
2. 레시피 상세 → **영양**에서 COOKRCP01 영양과 연결 후보를 구분해서 확인한다. 후보마다 근거·식품코드·기준량을 표시한다.
3. 레시피 상세 → **재료·장보기 → 관련 제품** 또는 **관련 제품** 탭에서 음식/재료별 가공식품 이름을 탐색한다.
4. 제품 선택 → 제조사·품목번호·원문 영양 → **공식 신고·원재료·안전 자료**에서 같은 번호의 원문 → **이 제품 구매처 검색**으로 이어진다. 원료·안전 원문 상세를 닫아도 부모 레시피·제품 화면을 유지한다. 원문 식별번호가 없으면 번호 연결 불가를 표시한다.
5. 음식 영양 상세에서도 음식명으로 연결된 레시피로 돌아갈 수 있다. 상세 원문을 닫아도 부모 레시피 화면을 유지한다.
6. 메인 숫자 검색에서 품목번호·과거 바코드를 정확히 조회한다. 원료명 검색에서는 공식 이름·이명 일치 자료와 사용 조건을 제공한다. 전체 7개 원본 검색은 `food-safety.html`에서 원본 종류를 선택하여 실행한다.
7. 조리법·주의성분 제외·저장 필터는 레시피 범위다. 제품을 안전한 음식으로 오해하지 않도록 적용 범위를 표시한다.

## 갱신과 검증

- 매일 06:20 KST 레시피 수집 후 연결 인덱스·수집 현황을 재생성하고 전체 포인터를 검증한 뒤 함께 반영한다.
- 주간 영양 수집은 원본 전수 검증·연결 재생성·검증 후 아티팩트로 보관한다. 이 작업 자체는 운영 main에 자동 반영하지 않는다.
- `python3 scripts/validate-food-links.py`: 전체 레시피와 1,284개 후보 포인터·소스 해시 검증.
- `node scripts/test-food-search.mjs`: 실제 압축본·Worker로 전체 건수, 이름 우선순위, 별칭, 초성, 코드, 제공단위량, 무결과, 제조사/제품명 검색 범위 및 JS/Python 연결 규칙 검증.
- 7개 API는 활용신청 승인 후 공식 전체 파일을 수집한다. CSV 인용부호·UTF-8 경계·gzip을 처리하고 원본 전체 파일, 정규화 JSONL, 행 수·고유 행 수·열·SHA-256을 보존한다. 원본 전체 파일과 실시간 API 총건수가 다르면 두 수를 별도로 기록한다. 같다고 검증한 것으로 표시하지 않는다.
- 정기 수집·인덱스 생성은 격리된 임시 세대에서 수행하고 원문·연결 검증 후 함께 main에 반영하여 Pages 빌드를 요청한다. 관리자 복구용 격리 데이터 브랜치 도구도 유지한다. API 키는 GitHub Secret에서만 사용하며 앱은 정적 자료만 조회한다.
- `scripts/validate-foodsafety.py`: 전체 원문 분할 파일의 해시·행 수·원본 필드 대조. `scripts/validate-foodsafety-index.py`: 원본별 전체 검색 포인터·256개 조회 버킷 해시·범위·총건수 검증. 상세를 열 때 원문 해시와 식별자를 확인한다.
- 대용량 품목·원재료 검색 인덱스는 사용자가 선택한 원본 하나만 Worker에서 읽는다. 메인 제품 상세 연결은 작은 번호 조회 버킷과 해당 원문 분할 파일만 읽는다.
- 기획상 남은 데이터: 재료 파싱 결과의 공식 원료코드 확정·사용 부위까지 검증하는 표준화, 현재 갱신되는 바코드 DB, 농진청/수산물 원재료 영양, 실시간 가격·리뷰. 확보·검증 전까지 연결 완료로 표시하지 않는다.

정기 수집 주기·실패 보존·자동 반영의 현재 기준은 [데이터 수집 운영 절차](DATA-COLLECTION-OPERATIONS.md)와 `config/collection-schedules.json`을 따른다. 과거 바코드 C005는 정기 재수집에서 제외한다.
